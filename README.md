# Импорт и каталог товаров

Slim 4, Doctrine ORM и PostgreSQL на бэкенде, Angular и NgRx на фронтенде. Файл `.xlsx` принимается сразу, а разбор и скачивание картинок выполняет воркер через Symfony Messenger и RabbitMQ.

Пример файла лежит в `samples/import-example.xlsx`.

## Запуск

```bash
cp .env.example .env
chmod +x deploy.sh
./deploy.sh
```

Тот же результат даёт `make up`. После сборки:

- приложение — http://localhost:8080
- Swagger — http://localhost:8080/api/docs
- RabbitMQ — http://127.0.0.1:15672 (логин и пароль из `.env`)

Вход по умолчанию: `admin@example.com` / `admin12345`. Пароль задаётся `ADMIN_PASSWORD` и записывается только если такого пользователя ещё нет. Смена переменной не обновляет уже созданную учётку.

Фикстуры трёх таблиц каталога:

```bash
make seed
```

Остановка: `make down`. Тома Postgres, RabbitMQ и файлов импорта сохраняются. Порт AMQP `5672` с хоста не открыт: `app` и `worker` ходят на `rabbitmq:5672`, снаружи доступна только панель http://127.0.0.1:15672.

Воркер стартует после миграций. При запуске он снова ставит в очередь задачи со статусом `pending` или `processing`. Если обработчик падает, задача переходит в `failed`.

Исходники в контейнеры не монтируются. После правок PHP или Angular пересоберите образы: `make up`.

Фронтенд в режиме разработки:

```bash
cd frontend
npm start
```

`ng serve` проксирует `/api` и `/media` на http://localhost:8080.

## Решения

- **Колонки с «упаковк»** — в картинки попадают только заголовки с «фото» / «изображ» или сочетание «ссылка» + «упаковк». Поля вроде «Вес упаковки» остаются атрибутами, иначе ломается приложенный `import-example.xlsx`.
- **Очередь в тестах** — PHPUnit использует `MESSENGER_TRANSPORT=in-memory`, чтобы не поднимать RabbitMQ; в Docker worker читает очередь `products_import` через AMQP.
- **Транзакции импорта** — каждая строка каталога сохраняется отдельной транзакцией вместе с атрибутами и успешно скачанными изображениями; ошибка одной строки не откатывает остальные.
- **NgRx на фронте** — каталог и импорт вынесены в feature state (`products`, `import`); HTTP остаётся в сервисах, side effects — в `@ngrx/effects`.

## Что делает импорт

Столбцы читаются по заголовкам, а не по номерам:

| Колонка | Куда попадает |
|---|---|
| Внешний код | `products.external_code`, уникальный ключ upsert |
| Наименование | `products.name` |
| Описание | `products.description` |
| Цена: Цена продажи | `products.price` |
| Закупочная цена | только для расчёта скидки |
| Доп. поле: * | `product_attributes.key` / `value`, префикс отрезается |
| Доп. поле с «фото» или «изображ», либо «ссылка» вместе с «упаковк» | ссылки скачиваются в `product_images`. «Вес упаковки» и размеры упаковки остаются атрибутами |

Скидка считается как `(цена продажи − закупочная цена) / цена продажи × 100` и округляется до двух знаков. Для строки примера `1320` и `880` это `33.33`.

Повторная загрузка того же внешнего кода обновляет товар, заменяет атрибуты и изображения и не создаёт дубликат. Пустая строка пропускается. Строка с пустым кодом, пустым названием, нечисловой ценой или формулой в ячейке попадает в отчёт и не откатывает остальные строки. Если картинка не скачалась, товар всё равно сохраняется, а ссылка остаётся предупреждением в отчёте.

Каждый товар записывается своей транзакцией вместе с атрибутами и успешно скачанными изображениями. Перед соединением адрес картинки проверяется: только `http`/`https`, порты 80 и 443, без редиректа во внутренние и служебные сети.

Файл импорта проверяется по расширению, размеру, MIME, сигнатуре ZIP и наличию `xl/workbook.xml`. На `POST /api/imports` стоит лимит запросов, по умолчанию 5 за 60 секунд на пользователя.

## API

| Метод | Путь | Доступ |
|---|---|---|
| GET | `/api/health` | открыт |
| POST | `/api/auth/login` | открыт |
| GET | `/api/products?page=1&limit=20&name=&priceMin=&priceMax=` | JWT |
| GET | `/api/products/{id}` | JWT |
| GET | `/api/products/export` | JWT |
| POST | `/api/imports` | JWT, rate limit |
| GET | `/api/imports/{id}` | JWT |

`POST /api/imports` отвечает `202` и id задачи. Прогресс читается опросом `GET /api/imports/{id}`: статус, проценты, счётчики и список ошибок строк.

## Проверки

```bash
make test
make phpstan
```

Нужен запущенный Postgres из compose: `make test` поднимает его сам. Набор включает разбор приложенного xlsx, расчёт скидки, CRUD товара с атрибутами и картинками и сквозной сценарий API: логин, очередь, фильтры, upsert, битая строка и лимит импорта.

## Состав

- `app` — PHP-FPM, multi-stage образ
- `worker` — тот же образ, команда `php bin/worker.php`
- `nginx` — собранный Angular и прокси `/api`
- `db` — PostgreSQL 16
- `rabbitmq` — очередь `products_import`, данные в томе `rabbitmqdata`

Переменные окружения описаны в `.env.example`.
